§1 System Overview

neox is a 32-bit x86 monolithic kernel written in C23 and NASM assembly. All code runs in Ring 0 (kernel mode). There is no user space yet. The entire task management stack — processes, threads, the scheduler, synchronisation — lives in kernel/task/ and is glued together by the interrupt infrastructure in kernel/arch/x86/.

The dependency graph flows strictly downward: nothing in a lower layer knows about a higher layer.

Fig 1 — Layer dependency graph. Arrows point from higher to lower layers. Nothing in a lower layer #includes a higher one.

§2 Boot Sequence & Interrupt Infrastructure

kernel_main is the C entry point after the GRUB bootloader hands over control. It calls kernel_init, then kernel_tests, then drops into the idle loop.

// kernel_main.c — the entire main function
kernel_init(magic, mb_info);   // hardware + memory + scheduler
kernel_tests();               // run all test suites
kernel_loop();                // hlt loop — becomes the idle thread

kernel_init calls subsystems in strict order. The tasking part is just two lines:

scheduler_init();    // zero the ready list, current = NULL
scheduler_start();   // register the boot stack as idle_thread
                     // ← from this point, timer ticks can preempt

Between those two calls, arch_init has already run, which enables interrupts and programs the PIT.

The PIT Timer & IRQ Path

The PIT is programmed at 100 Hz (10 ms per tick). Every tick generates IRQ0, which goes through the following chain:

PIT fires IRQ0 │ ▼ irq0: (irq_stubs.asm) cli ← interrupts disabled from here on push 0 ← error code placeholder push 32 ← interrupt number (IRQ0 = 32) jmp common_irq_stub │ ▼ common_irq_stub: pusha ← saves eax,ecx,edx,ebx,esp,ebp,esi,edi push ds/es/fs/gs ← saves segment registers mov ax, 0x10 → ds/es/fs/gs ← load kernel data segment push esp ← pass registers struct as argument call irq_handler ← C function add esp, 4 pop gs/fs/es/ds popa add esp, 8 ← pop int_no + error code iret ← restores EIP, CS, EFLAGS (re-enables IF if it was set) │ ▼ irq_handler() (irq.c) pit_handler() ← increments pit_ticks test_ticks++ pic_send_eoi(irq) ← ACK the PIC BEFORE scheduling decision if (irq == 0): scheduler_tick() │ ▼ if (--quantum_remaining > 0) return scheduler_switch() ← may never return to this thread │ ▼ scheduler_next() ← pick next thread quantum_remaining = 5 if (next == old) return context_switch(&old->kernel_sp, next->kernel_sp) ← CPU is now on a different stack
Fig 2 — Complete IRQ0 path from hardware to context switch
Why EOI before scheduler_tick? scheduler_tick may call context_switch, which switches to a different thread's stack. The current thread's stack frame in common_irq_stub is suspended indefinitely. If the PIC hadn't been acknowledged yet, IRQ0 would be permanently masked — no more ticks, no more preemption, the system freezes.

Interrupt Save / Restore

On the current uniprocessor x86 implementation, task synchronization relies on disabling local interrupts to prevent preemption during critical sections. interrupt_save() atomically captures EFLAGS and issues cli. interrupt_restore(state) pushes the saved EFLAGS back, re-enabling interrupts only if they were on.

// arch/x86/arch.c
interrupt_state_t interrupt_save(void) {
    interrupt_state_t state;
    __asm__ volatile(
        "pushf\n\t"   // push EFLAGS
        "pop %0\n\t"  // save to state
        "cli"         // disable interrupts
        : "=r"(state) :: "memory"
    );
    return state;       // caller must pass this to interrupt_restore
}

void interrupt_restore(interrupt_state_t state) {
    __asm__ volatile(
        "push %0\n\t" // push saved EFLAGS
        "popf"        // pop into EFLAGS — IF restored to original state
        :: "r"(state) : "memory", "cc"
    );
}

The pattern is used everywhere critical sections exist:

interrupt_state_t state = interrupt_save();   // cli, save IF
/* ... critical section ... */
interrupt_restore(state);                      // restore IF (sti if it was set)

§3 Data Structures

The Intrusive Linked List

Everything in neox is linked together using an intrusive doubly-linked list. Instead of allocating a separate list node that holds a pointer to the object, the list node is embedded directly inside the object. This means zero extra allocations and O(1) removal from any list given only a pointer to the node.

struct list_node { struct list_node *prev, *next; };
struct list      { struct list_node head; };  // sentinel
list.head ←→ thread_A.sched_node ←→ thread_B.sched_node ←→ (sentinel) (sentinel) ↑ container_of recovers thread_A from node pointer container_of(node, struct thread, sched_node) = (struct thread *)((char *)node - offsetof(struct thread, sched_node))
Fig 3 — Intrusive list. The sentinel's next/prev form a circular ring. An empty list has both pointing at the sentinel itself.

Crucially, list_remove sets both pointers to NULL after removal. list_push_* asserts they are NULL before insertion. This prevents double-insert bugs and lets the scheduler check node.next == NULL && node.prev == NULL to detect a removed-current-thread.

struct process

struct process {
    pid_t           pid;                         // monotonic, starts at 1
    char            name[32];                   // PROCESS_NAME_MAX
    struct list_node process_node;               // in global process_list
    struct list     threads;                     // owns thread group_nodes
};

A process is an ownership container — a name, a PID, and a list of threads. It has no address space yet (all processes share kernel_directory).

struct thread

§4 The Kernel Stack & Initial Layout

Each thread owns a PAGE_SIZE (4096 byte) kernel stack allocated from the heap. thread_create sets up the stack so that the first time context_switch restores this thread, execution begins at thread_bootstrap.

// Pointer starts at top-of-stack (high address), grows downward
stack = (uintptr_t *)((uint8_t *)thread->kernel_stack + THREAD_STACK_SIZE);

*--stack = (uintptr_t)thread_exit;      // [top-4]  safety net if entry() returns
*--stack = (uintptr_t)thread_bootstrap; // [top-8]  first IP via context_switch ret

context = (struct cpu_context *)(stack - 4); // 4 × uint32_t = 16 bytes
memset(context, 0, sizeof(*context));       // zeroed edi/esi/ebx/ebp
thread->kernel_sp = (uintptr_t)context;    // esp will point here on first switch

§5 Context Switch (Assembly Deep Dive)

context_switch(uintptr_t *old_sp, uintptr_t new_sp) is 9 lines of NASM. It saves the current thread's callee-saved registers, swaps the stack pointer, and restores the next thread's registers. The CPU then rets into whatever is on the new stack.

; Stack on entry (32-bit cdecl):
;   [esp+0]  = return address (inside scheduler_switch)
;   [esp+4]  = old_sp  (pointer to where we save current esp)
;   [esp+8]  = new_sp  (the value to load into esp)

context_switch:
    push ebp        ; save callee-saved registers
    push ebx
    push esi
    push edi
                    ; now esp has moved down 16 bytes, so:
                    ;   old_sp is at [esp+20]  (16 + 4 ret addr)
                    ;   new_sp is at [esp+24]

    mov eax, [esp + 20]   ; eax = old_sp (the pointer)
    mov [eax], esp         ; *old_sp = current esp → saved!

    mov eax, [esp + 24]   ; eax = new_sp (the value)
    mov esp, eax           ; CPU is now on the new thread's stack

    pop edi         ; restore new thread's saved registers
    pop esi
    pop ebx
    pop ebp

    ret             ; pop IP from new stack → jumps to thread_bootstrap (first run)
                    ;                      → or back into scheduler_switch (subsequent)
Thread A (being switched away from) Thread B (being switched to) Stack A: Stack B (first run): ┌──────────────────┐ ┌──────────────────┐ │ ... A's frames │ │ thread_exit addr │ │ scheduler_switch │ │ thread_bootstrap │ │ context_switch │ ├──────────────────┤ │ ret addr │ │ ebp = 0 │ │ old_sp ptr │ │ ebx = 0 │ │ new_sp val │ │ esi = 0 │ ├──────────────────┤ │ edi = 0 │ ← B's kernel_sp │ ebp │ └──────────────────┘ │ ebx │ │ esi │ │ edi │ ← A's kernel_sp written here After mov esp, eax: CPU is on Stack B After pop edi..ebp: B's saved regs restored (all zero on first run) After ret: jumps to thread_bootstrap → B now running
Fig 7 — What context_switch does to both stacks simultaneously.
The iret / ret asymmetry When a context switch happens inside the PIT interrupt handler (irq0 → common_irq_stub → irq_handler → scheduler_tick → context_switch), the thread that runs next gets there via ret, not iret. The ISR's iret never fires for that thread, so EFLAGS.IF is still clear — interrupts remain disabled. thread_bootstrap fixes this with an explicit interrupt_enable() as its very first instruction.

§6 The Scheduler

scheduler_start & the Idle Thread

After scheduler_init zeroes the ready list, scheduler_start registers the current execution context (the boot stack) as the idle thread:

static struct thread idle_thread;   // static, no allocated kernel_stack

void scheduler_start(void) {
    idle_thread.tid   = 0;           // tid=0 identifies it everywhere
    idle_thread.state = THREAD_RUNNING;
    scheduler_add(&idle_thread);      // push sched_node onto ready_list
    current = &idle_thread;          // it's running right now
    quantum_remaining = SCHEDULER_QUANTUM_TICKS;
}

From this point on, kernel_loop's hlt is interruptible, and a timer tick can switch away from the idle thread to any real thread added later.

Round-Robin Algorithm

scheduler_next() advances current one step forward in the ready list and wraps around. It never removes threads from the list — it only demotes the outgoing thread from RUNNING to READY and promotes the incoming thread to RUNNING.

struct thread *scheduler_next(void) {
    if (list_empty(&ready_list)) return NULL;

    if (current == NULL) {          // bootstrap: pick the first thread
        node = list_front(&ready_list);
    } else {
        if (current->state == THREAD_RUNNING)
            current->state = THREAD_READY;   // demote

        if (sched_node.next == NULL && sched_node.prev == NULL)
            node = list_front(&ready_list); // current was removed (blocked)
        else {
            node = list_next(&current->sched_node);
            if (node == &ready_list.head)
                node = list_front(&ready_list); // wrap around
        }
    }
    current = container_of(node, struct thread, sched_node);
    current->state = THREAD_RUNNING;
    return current;
}
ready_list (circular, sentinel = head node): head ←→ [idle tid=0] ←→ [A tid=1] ←→ [B tid=2] ←→ [C tid=3] ←→ head Round-robin steps (current starts at A): tick 1–5: A runs (quantum_remaining: 5→1) tick 6: quantum = 0 → scheduler_next() picks B A demoted to READY, B promoted to RUNNING tick 7–11: B runs tick 12: C runs tick 13: idle runs (if idle is still in list) tick 14: A runs again ← wrap around
Fig 8 — Round-robin step-through with 3 threads + idle in the ready list.

Preemption: The Tick Path

PIT fires (every 10ms at 100Hz) │ ▼ irq_handler → scheduler_tick() │ ├─ if current == NULL: return (scheduling not started) ├─ if --quantum_remaining > 0: return (quantum not expired) └─ scheduler_switch() │ old = current next = scheduler_next() ← advances round-robin quantum_remaining = 5 ← reset unconditionally │ ├─ if next == old: return ← only one runnable thread └─ context_switch(&old->kernel_sp, next->kernel_sp) │ ← old thread is suspended here → next thread resumes from its kernel_sp

Cooperative: The Yield Path

A thread can voluntarily hand the CPU to the next thread by calling thread_yield(). This goes through the same scheduler_switch but is triggered by the thread itself rather than a timer.

void thread_yield(void) {
    if (scheduler_current() == NULL) return;
    interrupt_state_t state = interrupt_save();  // cli
    scheduler_yield();                           // → scheduler_switch()
    interrupt_restore(state);                   // sti (when we return)
}

Quantum Mechanics

Quantum reset even on same thread scheduler_switch resets quantum_remaining = 5 unconditionally, even if next == old (meaning the thread runs again). This means a thread that is the only runnable thread always gets a fresh 5-tick quantum after each "switch" decision, rather than accumulating.

§7 Thread Lifecycle — All Paths

Creation: thread_create

Creating a thread allocates the struct, sets up the kernel stack, and returns — but does not add the thread to the scheduler. The caller must call thread_add separately (under interrupt disable).

Call thread_add() next. thread_add(thread) ← caller must hold interrupts off 1. list_push_back(&process->threads, &thread->group_node) 2. scheduler_add(thread) ← pushes sched_node to ready_list tail

First Run: thread_bootstrap

The very first time a thread gets CPU time, context_switch's ret lands in thread_bootstrap. This function has two critical jobs before it ever calls entry():

static void thread_bootstrap(void) {
    interrupt_enable();           // ← CRITICAL: cli from the ISR is still in effect
    struct thread *t = scheduler_current();
    t->entry();                   // run the user-provided function
    thread_exit();                // if entry() returns
}

Without interrupt_enable(), the thread would run to completion with all timer interrupts masked — no preemption ever, and no other thread would run.

Blocking & Unblocking

thread_block() is the self-blocking primitive. It's called directly (by code that wants to block itself without a specific wait queue) or indirectly through wait_queue_sleep.

void thread_block(void) {
    interrupt_state_t state = interrupt_save();
    thread->state = THREAD_BLOCKED;
    scheduler_remove(thread);     // pulls sched_node from ready_list
    scheduler_yield();            // switch to another thread NOW
    interrupt_restore(state);    // reached only after thread_unblock + reschedule
}

The interrupt_restore at the end runs when this thread is eventually unblocked and runs again — it resumes exactly from that point in the stack frame.

void thread_unblock(struct thread *thread) {
    ASSERT(thread->state == THREAD_BLOCKED);
    interrupt_state_t state = interrupt_save();
    thread->state = THREAD_READY;
    scheduler_add(thread);       // pushes back onto ready_list
    interrupt_restore(state);
    // caller decides when to yield — the unblocked thread competes normally
}

Termination: thread_exit

static void thread_exit(void) {
    interrupt_save();             // cli (return value discarded — BUG, should be interrupt_disable)
    struct thread *thread = scheduler_current();
    scheduler_terminate(thread);  // remove from ready_list, TERMINATED, wake_all(termination_queue)
    scheduler_yield();            // switch away — this thread never runs again
    panic("terminated thread resumed");  // should never reach here
}

void scheduler_terminate(struct thread *thread) {
    ASSERT(!interrupt_enabled());
    scheduler_remove(thread);         // out of ready_list
    thread->state = THREAD_TERMINATED;
    wait_queue_wake_all(&thread->termination_queue); // wake thread_wait() callers
}

Joining: thread_wait

thread_wait(target) blocks the caller until target terminates. It sleeps in target->termination_queue. The race window between the check and the sleep is closed by the surrounding interrupt_save.

void thread_wait(struct thread *thread) {
    interrupt_state_t state = interrupt_save();  // cli — close TOCTOU window
    if (thread->state != THREAD_TERMINATED)
        wait_queue_sleep(&thread->termination_queue);
    interrupt_restore(state);
    // returns only after target is TERMINATED
}

§9 Mutex

struct mutex {
    struct thread    *owner;       // NULL = unlocked
    struct wait_queue wait_queue;  // threads waiting to acquire
};

Lock Path

void mutex_lock(struct mutex *mutex) {
    if (mutex->owner == NULL) {          // ← BUG: not interrupt-guarded
        mutex->owner = scheduler_current();
        return;
    }
    interrupt_state_t state = interrupt_save();
    wait_queue_sleep(&mutex->wait_queue); // blocks until unlock transfers ownership
    interrupt_restore(state);
}

Unlock & Ownership Transfer

void mutex_unlock(struct mutex *mutex) {
    ASSERT(mutex->owner == scheduler_current());
    struct thread *thread = wait_queue_remove(&mutex->wait_queue);
    if (thread != NULL) {
        mutex->owner = thread;           // ← direct transfer, no NULL gap
        thread_unblock(thread);
        return;
    }
    mutex->owner = NULL;
}
Lock scenario: A holds, B and C waiting mutex.owner = A mutex.wait_queue = [B] ←→ [C] A calls mutex_unlock(): 1. wait_queue_remove() → pops B 2. mutex.owner = B ← ownership never drops to NULL 3. thread_unblock(B) ← B goes back on ready_list wait_queue = [C] (C still waiting) mutex.owner = B Next: B eventually calls mutex_unlock() → C gets ownership the same way

§10 Semaphore

struct semaphore {
    uint32_t         count;       // current count
    struct wait_queue wait_queue;
};
void semaphore_acquire(struct semaphore *sem) {
    if (sem->count > 0) { sem->count--; return; }   // ← BUG: not guarded
    interrupt_state_t state = interrupt_save();
    wait_queue_sleep(&sem->wait_queue);
    interrupt_restore(state);
    // note: count NOT decremented here — release handles it via handoff
}

void semaphore_release(struct semaphore *sem) {
    struct thread *thread = wait_queue_remove(&sem->wait_queue);
    if (thread != NULL) { thread_unblock(thread); return; }
    sem->count++;                                  // ← BUG: not guarded
}
The handoff model When a waiter exists, semaphore_release does NOT increment count. The release "gives its slot" directly to the woken thread. count stays at 0. This keeps the invariant: count is the number of available resources when no one is waiting, not an absolute counter of all releases.

§11 Race Conditions — Complete Analysis

The x86 UP Race Model

neox runs on a single CPU. There is no true parallelism. The only way two threads can "interleave" is if a PIT interrupt fires between two instructions. Therefore:

  • Any sequence of instructions that is not interrupted is atomic.
  • A race condition exists wherever a timer interrupt between two instructions leaves shared state inconsistent.
  • The fix is always the same: interrupt_save() before the check, interrupt_restore() after the write.

Race 1 — mutex_lock Fast Path BUG

Thread A PIT fires here Thread B mutex_lock(m): if (m->owner == NULL) ← TRUE, proceeds ↕ interrupt scheduler_switch → B runs mutex_lock(m): if (m->owner == NULL) ← still NULL! m->owner = B ← B claims it B continues, holds mutex... tick expires → A resumes m->owner = A ← A ALSO claims it Result: both A and B believe they hold the mutex. Critical section is not exclusive.
Fig 14 — mutex_lock fast-path race. A timer interrupt between the NULL-check and the assignment corrupts ownership.

Fix: wrap the entire fast path in interrupt_save / interrupt_restore.

Race 2 — semaphore_acquire Fast Path BUG

sem.count = 1 Thread A PIT fires here Thread B semaphore_acquire(sem): if (sem->count > 0) ← TRUE (count=1) ↕ interrupt → B runs semaphore_acquire(sem): if (sem->count > 0) ← still 1 sem->count-- ← count = 0 B holds resource tick expires → A resumes sem->count-- ← count = 0xFFFFFFFF (uint32 underflow!) Result: both threads acquired a semaphore with count=1. count wraps to UINT32_MAX.
Fig 15 — semaphore_acquire fast-path race. uint32_t underflow wraps to 4 billion.

Race 3 — Unlock/Release Structural Gap BUG

Thread A (holding mutex) PIT fires here Thread C mutex_unlock(m): thread = wait_queue_remove() ← B removed from queue ↕ interrupt → C runs mutex_lock(m): if (m->owner == NULL) ← TRUE, m->owner not yet set! m->owner = C ← C claims it tick → A resumes m->owner = B ← A overwrites C's claim thread_unblock(B) ← B also gets ownership Result: both B and C believe they own the mutex. m->owner = B but C also holds it.
Fig 16 — mutex_unlock structural race. The window between remove and owner-assignment allows a new lock to sneak in.

Bug 4 — thread_exit Discards interrupt_save Return Value BUG

static void thread_exit(void) {
    interrupt_save();    // ← return value discarded — the cli side-effect is intentional
                         // but the semantics are wrong. Should be: interrupt_disable()
    ...
}

The code works because the side effect of interrupt_save() is always cli. But discarding the return value signals to a reader that "I want to save and restore" when the real intent is "I want to disable permanently (the thread is dying)". Use interrupt_disable().

Scenario A — Preemptive Round-Robin (3 threads)

ready_list: [idle] ←→ [A] ←→ [B] ←→ [C] quantum=5 Ticks 1–5: A runs (A's entry() executing) tick 5: --quantum_remaining → 0 scheduler_switch() scheduler_next(): A→READY, advance to B, B→RUNNING quantum_remaining = 5 context_switch(&A.kernel_sp, B.kernel_sp) → B's stack loaded, pop edi/esi/ebx/ebp, ret → B's last IP Ticks 6–10: B runs tick 10: quantum → 0, switch to C Ticks 11–15: C runs tick 15: quantum → 0, switch to idle Ticks 16–20: idle runs (kernel_loop hlt) tick 20: switch back to A (wrap around) State at each switch: outgoing thread: state = READY (still in ready_list) incoming thread: state = RUNNING idle thread: always in list, gets time when it's its turn

Scenario B — Thread Blocks on Mutex

§13 Interrupt Discipline Reference Card

The single rule: interrupts must be off whenever you touch scheduler state (ready_list, current, quantum) or shared per-thread state (thread state, wait_queue pointer).

The pattern to follow for all future synchronization primitives Every function that reads-then-writes shared state must wrap the entire read-check-write sequence in a single interrupt_save / interrupt_restore pair. The save must happen before the first read, not after. The restore happens after the last write. Anything in between is atomic from the scheduler's perspective.
